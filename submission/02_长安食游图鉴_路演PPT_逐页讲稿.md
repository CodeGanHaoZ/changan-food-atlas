# 长安食游图鉴｜路演 PPT 逐页讲稿

建议时长：4 分 30 秒至 5 分钟。现场以真实 Demo 操作为主，PPT 用来建立问题、方案、技术和价值的叙事。

## 01｜封面｜20 秒

标题：长安食游图鉴

副标题：先看懂一味，再走进一街

讲稿：游客来到西安，常常知道“想吃肉夹馍”，却不知道去哪找、怎么吃、如何在有限时间里串起几种真正有地方特色的味道。长安食游图鉴把菜品文化、真实地点和路线决策放进同一条链路。

## 02｜问题｜30 秒

页面信息：

- 菜品知识分散在攻略、短视频和百科；
- 地点、价格、营业信息分散在点评和地图；
- 网红店、老字号、巷子小店和街边摊难以比较；
- 排队、歇业或时间不够时没有备用方案。

讲稿：现在的工具通常只解决“看评价”“看地图”或“看攻略”其中一个问题，用户仍然要自己拼接一次完整的美食探索。

## 03｜方案｜30 秒

页面信息：

```text
理解一道菜 → 找到真实地点 → 选择吃法 → 规划一段路线
```

讲稿：我们从一道菜开始，让用户先看懂它的历史、食材和吃法，再进入能找到这道菜的店铺、街区或巷子，最后根据时间、预算和消费方式生成路线。

## 04｜产品入口｜30 秒

页面信息：

- 首页图鉴轮播；
- 14 道西安及陕西特色菜品；
- 菜品详情：历史、食材、调味、做法、来源；
- 收集册：全量浏览和搜索。

讲稿：打开首页先看到菜品，而不是一张空地图。肉夹馍、泡馍、凉皮、油泼面等菜品通过图片和文化短句建立第一印象，点击后进入可追溯的详情。

现场动作：点击一张菜品卡片，打开详情弹窗，滚动展示历史来源和“味与法”。

## 05｜从菜品到地点｜35 秒

页面信息：

- 门店名称、区域、地址和经纬度；
- 人均价格、菜系、营业时间；
- 堂食、外带、交通指南等服务；
- 关联菜单和距离定位。

讲稿：图鉴不是看完就结束。门店资料展示游客真正需要的决策字段。用户可以只买一道菜，也可以在不同地点分散购买多种小吃，不被“一桌菜”限制。

现场动作：点击“沿街拾味”中的门店，展示菜单、地址和定位距离；再点击关联菜品回到图鉴详情。

## 06｜路线 Demo｜40 秒

输入示例：钟楼附近 · 2 小时 · 3 种小吃 · 不想去连锁店

页面信息：

- 起点、节点和顺序；
- 预计时长与预算；
- 多地点串联；
- 来源和降级状态。

讲稿：用户不需要先学会筛选器，只要说出自己的条件。Agent 负责理解地点、时间、预算和偏好，路线程序负责计算节点、预算和时长，接口失败时仍能用本地资料完成演示。

现场动作：点击预设“钟楼听钟”或手动输入条件，展示路线面板。

## 07｜来源与真实性｜30 秒

页面信息：

- 游陕西小程序与用户提供截图：菜品、店铺和榜单参考；
- 百度百科公开词条：历史与基本形制；
- 更新版 `xian-food-map.html`：菜品图片提示参考；
- Wikimedia Commons：缺图时的公开媒体库候选；
- 价格、营业和评分保留采集时间与待确认状态。

讲稿：我们把“来源”做成产品的一部分。演示 seed 数据会明确标注为演示资料，不把它包装成实时商家事实；正式提交前逐条替换为官方菜单、商家确认或可核验的公开资料。

## 08｜技术架构｜35 秒

页面信息：

```text
React/Vite UI
  ├─ 图鉴与详情
  ├─ 店铺与菜单关联
  ├─ Agent 条件输入
  └─ 路线与来源
        ↓
本地结构化数据 + Agent 适配器 + 确定性路线规则 + 天地图
```

讲稿：AI 负责理解和编排，程序负责距离、预算、营业和来源状态。这样的分工可以解释、可回退，也不会让模型凭空生成价格和营业信息。

## 09｜创新与商业价值｜35 秒

页面信息：

- 3D/图片化菜品图鉴连接真实地点；
- 一道菜对应多个地点和消费方式；
- 多地点路线与 Plan B；
- 面向酒店、旅行社、餐厅和文旅街区的内容与客流工具。

讲稿：我们不做西安版大众点评，也不做通用地图或交易平台。差异在于把地方文化内容转化为具体的到店和行走决策，后续可以为商家、酒店和街区提供可维护的菜品与路线资产。

## 10｜落地计划与结尾｜25 秒

页面信息：

- P0：真实来源、核心菜品素材、现场 Demo；
- P1：商家维护、多路线比较、轻量 3D；
- P2：审核后台、用户投稿和商业化接口。

讲稿：今天的 Demo 已经跑通从看菜、看店到路线的主流程。下一步是把演示资料逐条换成可核验数据，把图片和模型的授权信息补齐，再将这套能力交给酒店、旅行社、餐厅和文旅街区使用。长安食游图鉴，希望让游客先看懂一味，再走进一街。

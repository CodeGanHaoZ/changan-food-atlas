# 长安食游图鉴｜项目说明文档

## 1. 项目概述

“长安食游图鉴”是一款面向西安游客与本地用户的在地美食探索工具。产品以西安特色菜品图鉴为入口，将菜品文化、真实地点、消费方式、路线规划和来源信息放在同一个决策链路中，帮助用户回答四个问题：这是什么、去哪找、怎么吃、怎样串起来更合适。

项目不定位为综合点评平台，也不提供支付、外卖或团购履约。它聚焦于西安地方美食的文化理解和出行决策。

## 2. 参赛问题

游客在西安寻找美食时，常见信息被分散在攻略、短视频、点评、地图和店铺菜单中：

- 只知道菜名，不知道历史、食材和正确吃法；
- 看到推荐后，不知道应该去老字号、美食街、巷子小店还是街边摊；
- 价格、评分、营业状态和菜单信息缺少统一来源与时间标记；
- 想在有限时间内吃多种小吃，却需要手动比较地点、距离和预算；
- 目标店铺排队或暂停营业时，缺少可解释的替代方案。

## 3. 产品方案

产品形成“看懂一味 → 找到一处 → 选择吃法 → 规划一程”的闭环：

1. 在首页轮播和图鉴列表中浏览西安特色美食；
2. 点击菜品查看历史、食材、调味、做法和历史资料来源；
3. 从菜品进入关联店铺，查看区域、人均价格、营业时间、消费方式和地址；
4. 开启定位后计算用户与门店的距离；
5. 输入“钟楼附近、两小时、三种小吃”等自然语言条件；
6. 由 Agent 适配器解析条件，再由路线规则计算路线、预算、时长和风险；
7. 网络或接口失败时回退到本地演示资料，保证 Demo 可运行。

## 4. 当前 Demo 范围

### 已实现

- React 18 + Vite 可运行前端；
- 首页 Hero 菜品轮播，支持自动切换、左右箭头和详情入口；
- 菜品卡片和收集册页面；
- 14 道西安及陕西特色菜品资料结构；
- 菜品详情弹窗：历史、百度百科链接、食材、调味、做法；
- 食品图片优先使用更新后的 `xian-food-map.html` 图片提示，缺图回退 Wikimedia Commons 公开图片候选；
- 店铺列表与店铺详情弹窗；
- 菜单菜品与图鉴详情的关联跳转；
- 天地图加载成功时展示门店点位，加载失败时提供明确降级提示；
- 浏览器定位后展示门店距离；
- 自然语言探索输入、预设条件和路线生成；
- 来源抽屉与页脚数据来源说明；
- 移动端底部导航、响应式卡片和主题滚动条；
- 长安墨朱砂风格：墨色背景、朱砂强调、鎏金细线、宣纸正文和 MingCute 图标。

### 现场演示路径

1. 打开首页，展示肉夹馍、凉皮或羊肉泡馍图片与菜品说明；
2. 点击“查看菜品详情”，展示历史、来源、食材、调味和做法；
3. 返回首页进入“沿街拾味”，点击门店查看人均、菜系、营业时间、地址、距离和推荐菜单；
4. 点击“开启定位”，演示距离字段从“定位后显示距离”变为公里数；
5. 在“写下你的寻味条件”输入“钟楼附近 · 2 小时 · 3 种小吃”，生成路线方案；
6. 打开“查看来源”，说明游陕西截图、公开百科资料和图片来源；
7. 缩窄浏览器窗口，演示移动端底部导航和纵向布局。

## 5. 菜品与资料范围

当前图鉴收录：肉夹馍、凉皮、泡馍、甑糕、水盆羊肉、岐山臊子面、锅盔、乾县豆腐脑、油泼面、biangbiang 面、葫芦鸡、肉丸胡辣汤、柿子饼、荞面饸饹。

菜品字段包括：

- 菜名、分类、风味短句；
- 喜爱值或评分展示值；
- 食材、调味和制作步骤；
- 历史摘要与公开资料链接；
- 菜品图片提示与公开图片候选；
- 关联地点和菜单菜品 ID。

店铺字段包括：

- 门店名称、类型、区域、地址和经纬度；
- 人均价格、菜系、营业时间和消费方式；
- 服务标签、收录标签、门店简介和推荐菜单；
- 距离计算所需的坐标字段；
- 游陕西小程序截图来源标记。

## 6. 数据真实性边界

当前 `src/data/atlasSeed.js` 中的地点、价格、评分、营业时间和路线仍是用于演示信息架构的 seed 数据。它们不能在路演中被表述为平台实时事实。正式提交前应逐条替换为可核验记录，或者在页面上保持“演示 / 待确认”状态。

数据来源优先级：官方菜单或商家确认、店内菜单照片、游陕西等官方小程序、景区或街区官方资料、博物馆/地方志/政府文旅资料、公开地图 POI、公开评分页面和真实访谈。

历史内容当前以百度百科公开词条作为入门资料，并在菜品详情中保留链接。图片优先读取用户提供的更新版 `xian-food-map.html` 同源图片提示，缺失时尝试 Wikimedia Commons 公开媒体库；图片版权、署名和原文件页说明应在正式发布前逐项复核。

## 7. 技术架构

```text
React UI
  ├─ 图鉴首页 / 菜品详情 / 收集册
  ├─ 店铺列表 / 店铺详情 / 菜单关联
  ├─ Agent 条件输入 / 路线面板
  └─ 来源抽屉 / 移动端导航
        │
        ├─ src/data/atlasSeed.js       菜品、地点、来源登记
        ├─ src/services/agentApi.js    自然语言解析适配器与规则回退
        ├─ src/services/routeApi.js    路线、预算、时间计算
        └─ TianDiMap                   地图加载与点位展示
```

技术选型：

- React 18 + Vite：页面脚手架和交互状态；
- 原生 CSS Tokens：响应式布局和长安墨朱砂主题；
- Iconify MingCute：本地注册图标，避免混用图标库；
- 本地结构化数据：断网也能完成主流程；
- 天地图 API：可用时展示门店点位，失败时保留降级页面；
- Agent/路线适配器：模型只负责理解条件，距离、预算和路线由程序计算。

## 8. AI 使用边界

AI 适合承担：

- 将用户自然语言拆成地点、时间、预算、菜品和消费方式；
- 根据结构化菜品与地点资料生成解释性推荐；
- 编排多个地点的探索顺序和文字说明。

程序规则负责：

- 距离、预算和时长计算；
- 消费方式筛选；
- 营业时间冲突提示；
- 来源状态、采集时间和待确认标记。

在数据缺失时，系统不应让模型猜测价格、评分、营业状态、过敏原或历史事实。

## 9. 商业价值

### 用户价值

- 降低游客理解地方美食的门槛；
- 减少在多个 App 之间来回搜索和比较的时间；
- 支持单品购买、街区漫游、巷子小店和分散式多人探索；
- 用来源和时间标记提升推荐可信度。

### 商业价值

- 餐厅：展示特色菜与文化内容，获得更精准的到店客流；
- 酒店与民宿：提供可复用的本地美食接待方案；
- 旅行社与地接：快速生成美食与游览路线；
- 美食街与文旅街区：把文化内容转化为可执行的消费路径；
- 地方文旅平台：沉淀具有城市辨识度的数字化美食资产。

首期不虚构收入指标，建议用路线规划耗时、用户理解度、路线完成率、备选方案采用率和信息有效率进行验证。

## 10. 创新性与竞品边界

项目的差异点是“菜品文化图鉴 + 真实地点图谱 + 多种消费方式 + 多地点路线”。它不替代大众点评的点评和交易、不替代美团的履约、不替代高德的导航，也不复制小红书的信息流。

核心创新：

1. 从一道菜进入真实地点，而不是停留在百科介绍；
2. 同一菜品支持堂食、外带、打包、街边购买等不同消费方式；
3. 用 Agent 理解需求，用确定性程序校验预算、距离、营业和来源；
4. 为排队、歇业或信息过期提供可解释的 Plan B；
5. 让地方文化内容直接服务于用户的出行与购买决策。

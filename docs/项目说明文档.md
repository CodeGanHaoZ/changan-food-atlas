## 1. 项目概述

长安食游图鉴是一个以西安美食图鉴为入口的在地探索决策工具。它把「认识一道菜」和「去哪吃、怎么吃」连接起来：用户先通过图鉴了解菜品的历史、食材与吃法，再通过天地图上的真实店铺标注找到去处，最后用自然语言描述条件，生成一条可执行的美食探索路线。

### 1.1 定位

> 面向西安地方美食的城市文化图鉴和在地探索决策工具。

不是大众点评的替代品，不是美团的交易平台，不是高德地图的导航工具，也不是普通攻略生成器。

### 1.2 核心闭环

```text
浏览美食图鉴
→ 了解历史、食材与吃法
→ 查看真实美食地点
→ 选择堂食、外带、街边购买或路线串联
→ 生成美食探索方案
→ 查看价格、营业状态和数据来源
→ 选择购买或前往
```

## 2. 功能架构

### 2.1 页面结构

```text
首页（Home）
├── Hero · 当前图鉴轮播（前 8 道菜，3.6s 自动切换）
├── 去哪吃怎么吃（条件输入 + 方案生成）
├── 循味成行（天地图 + 店铺标注 + 路线站点）
├── 沿街拾味（店铺列表，默认 3 家）
└── 风味入长安（菜品卡片网格，最多 8 道）

收集册页（Collection）
└── 全部 14 道菜品，一行四个网格陈列

店铺列表页（Places）
└── 全部 7 家店铺，纵向卡片流
```

### 2.2 核心交互

| 交互 | 说明 |
|---|---|
| 轮播 | Hero 区自动轮播，左右箭头/圆点手动切换，弹窗打开时暂停 |
| 菜品详情弹窗 | 图片、历史、食材、步骤、喜爱值、标签，来源可跳转百科 |
| 条件生成方案 | 输入自然语言条件，规则解析后生成路线，地图标注同步切换 |
| 地图信息卡片 | 点击地图标注弹出底部卡片，展示店铺/站点摘要，可直达详情 |
| 来源札记 | 展示全部数据来源、采集时间、验证状态 |
| 返回顶部 | 滚动超阈值显示，回到顶部后触发滚动动画重置 |

### 2.3 动效体系

- 滚动渐入：所有板块、卡片、面板进入视口时上浮淡入，带错落延迟
- 弹窗：打开时缩放淡入，关闭时缩放淡出，内容分块错落入场
- 轮播切换：图片与文字分块上浮，卡片切换时同步
- 返回顶部后：所有动画重置，再次滚动重新播放
- `prefers-reduced-motion` 时全部降级为直接显示

## 3. 技术架构

### 3.1 技术选型

| 层 | 实现 | 选择理由 |
|---|---|---|
| 前端 | React 18 + Vite | 快速脚手架、组件化、现场启动稳定 |
| 地图 | 天地图 Web API v4.0 | 免费额度、覆盖西安、真实 POI 标注 |
| 图标 | `@iconify/react` + MingCute | 本地注册，断网可演示 |
| 样式 | 原生 CSS Tokens | 墨底、朱砂、鎏金、宣纸四色体系 |
| 数据 | 本地结构化 seed + source registry | 断网可演示，字段预留真实数据接入 |
| Agent | `agentApi` 规则解析 | 大模型接入边界已保留 |
| 视觉 | `changan-ink-ui` | 国风深色范式，MingCute 线性图标 |

### 3.2 目录结构

```text
src/
  main.jsx                 页面组装、导航、地图组件和交互状态
  styles.css               主题 token、组件样式、响应式和动效
  data/atlasSeed.js        14 道菜品、7 家店铺和来源登记
  services/atlasApi.js     菜品/地点/来源查询适配器
  services/agentApi.js     自然语言解析适配器与规则回退
  services/routeApi.js     确定性路线、预算和风险计算
public/
  motifs/                  长安墨朱砂西安纹样（SVG）
  brand/                   品牌 Logo 与西客松赛事 Logo
docs/                      项目文档
vite.config.js             GitHub Pages base 路径配置
```

### 3.3 构建与部署

```bash
npm install        # 安装依赖
npm run dev        # 开发服务器（默认 5173）
npm run build      # 生产构建到 dist/
npm run preview    # 本地预览构建产物
```

## 4. 数据模型

### 4.1 菜品（Dish）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识 |
| `name` | string | 菜品名称 |
| `category` | string | 分类（如「小吃 · 主食」） |
| `note` | string | 一句话描述 |
| `score` | string | 喜爱值（来自游陕西截图或默认 90.0） |
| `scoreIsDefault` | boolean | 是否为展示规则补的默认值 |
| `tags` | string[] | 标签（人气榜/外带/堂食等） |
| `ingredients` | string[] | 主要食材 |
| `seasoning` | string[] | 调味 |
| `history` | string | 历史文化说明 |
| `historySourceIds` | string[] | 历史来源 ID |
| `steps` | string[] | 制作步骤 |
| `sourceIds` | string[] | 全部来源 ID |
| `imagePrompt` | string | AI 文生图提示词 |

### 4.2 店铺（Place）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 唯一标识 |
| `name` | string | 店铺名称 |
| `type` | string | 类型（肉夹馍店/陕菜餐馆等） |
| `area` | string | 区域 |
| `dish` | string | 主打菜品 |
| `averagePrice` | string | 人均价格 |
| `cuisine` | string | 菜系 |
| `openingHours` | string | 营业时间 |
| `services` | string[] | 服务（堂食/外带/交通指南等） |
| `address` | string | 地址 |
| `tags` | string[] | 标签 |
| `collections` | string[] | 收录榜单 |
| `intro` | string | 简介 |
| `menu` | object[] | 推荐菜单（可关联菜品 ID） |
| `mode` | string | 消费方式 |
| `longitude` / `latitude` | number | 天地图坐标（演示坐标） |
| `sourceIds` | string[] | 来源 ID |

### 4.3 来源（Source）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识 |
| `title` | string | 来源名称 |
| `kind` | string | 类型（app/place/image/rule/history） |
| `capturedAt` | string | 采集时间 |
| `verification` | string | 验证状态 |
| `note` | string | 说明 |
| `url` | string? | 原始链接 |

### 4.4 来源清单

| 来源 | 类型 | 用途 |
|---|---|---|
| 游陕西小程序 · 人气美食排行榜 | app | 菜品名称、榜单分值、图片参考 |
| 游陕西小程序 · 店铺榜单 | place | 店铺名称、分店、展示图片 |
| Wikimedia Commons | image | 菜品公开图片直链候选 |
| 百度百科词条（每道菜一条） | history | 历史与基本形制参考 |
| 展示规则 · 缺失评分默认值 | rule | 评分缺失时补 90.0 的展示规则 |

## 5. API 契约

```ts
type ExploreQuery = {
  origin?: string;
  durationMin?: number;
  budgetMax?: number;
  dishes?: string[];
  modes?: ('dine_in' | 'takeaway' | 'packaged' | 'street')[];
  avoidChains?: boolean;
};

type RoutePlan = {
  title: string;
  stops: Array<{ placeId: string; dishIds: string[]; mode: string }>;
  durationMin: number;
  budgetRange: [number, number];
  risks: string[];
  alternatives: string[];
};

// services/agentApi.js
async function parseExploreQuery(input: string): Promise<ExploreQuery>;

// services/routeApi.js
async function buildRoute(query: ExploreQuery): Promise<RoutePlan>;

// services/atlasApi.js
async function getAtlas(filters?: { dishId?: string; category?: string }): Promise<Dish[]>;
async function getPlaces(filters?: { dishId?: string; area?: string; mode?: string }): Promise<Place[]>;
```

### 5.1 Agent 边界

大模型接入时只负责理解和编排（`parseExploreQuery`），价格、距离、营业、预算和来源状态仍由程序校验（`buildRoute`）。当前为本地规则解析，断网可演示。
